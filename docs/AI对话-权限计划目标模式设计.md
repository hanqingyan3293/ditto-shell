> 从 DSH（DeepSeek Harness）的实现学习，适配到 DittoShell 的剪贴板场景。

## 一、DSH 是怎么做的（源码实证）

### 1.1 权限预设（`dsh-permission-presets`）

**本质**：两个正交维度捆绑成预设。

```yaml
presets:
  workspace-write:
    sandbox: workspace-write      # 沙箱限制
    approval: ask                 # 审批策略
  danger-full-access:
    sandbox: danger-full-access
    approval: never
```

| 维度 | 取值 | 含义 |
|---|---|---|
| `sandbox` | `read-only` / `workspace-write` / `danger-full-access` | 能碰什么 |
| `approval` | `ask` / `never` | 要不要问 |

**关键设计**：
- 预设只是**捆绑**，沙箱和审批各自保留独立取值
- 不匹配任何预设的组合显示为 `custom`
- **执行层（沙箱/审批）和控制层（预设选择）解耦**

### 1.2 计划模式（`dsh-plan-mode`）

**本质**：**prompt 注入 + 一个退出工具**，不限制能力。

```yaml
config:
  section: |
    You are in plan mode. Explore and design before presenting the complete
    plan through exit_plan_mode.
```

**流程**：
```
/plan <message>
  ↓
注入 plan:policy 提示词段
  ↓
AI 只探索（search / read / grep），不写
  ↓
AI 调 exit_plan_mode(plan)
  ↓
用户看到计划 → [批准执行] / [继续规划(带反馈)]
  ↓
批准 → 退出计划模式，AI 开始执行
```

**源码里明确写的**：

> 「它不限制 agent：每个工具仍可调用，因此需要强制限制时请使用沙箱模式与审批提示。」

**这说明**：**计划模式是「约定」，不是「强制」**。真正的限制靠权限系统。

### 1.3 目标模式（`dsh-goal` + `dsh-goal-round-driver`）

**本质**：**持久化目标 + 自动续跑轮次**。

```yaml
config:
  defaultMaxGoalRounds: 256
```

**状态机**：
```
active ──┬── complete ──→ completed
         ├── pause ─────→ paused ──resume──→ active
         └── blocked ───→ blocked（3+ 轮同一阻塞条件）
```

**核心机制**（`goal-round-driver`）：

```
第 1 轮：AI 干活 → 检查 goal 是否完成
   ├─ 完成 → 停止
   └─ 未完成 → 自动发起第 2 轮
第 2 轮：…
…
最多 256 轮
```

**关键设计**：
- **每会话只有一个 active goal**（不能并行）
- 跨会话恢复 / fork / 进程重启都保留
- **`blocked` 需要连续 3 轮同一阻塞条件**才允许（防止轻易放弃）
- `update_goal` 用 **compare-and-set**（revision）防并发覆盖

## 二、DittoShell 的适配设计

### 2.1 场景差异

| 维度 | DSH | DittoShell |
|---|---|---|
| 任务 | 写代码（文件增删改） | 查/改剪贴板条目 |
| 危险操作 | `rm -rf` / `git push` | **删除条目** / 批量改分组 / 写 Ditto.db |
| 数据规模 | 文件系统 | 2,000 条剪贴板 |
| 不可逆 | 文件删除 | 条目删除（有备份） |

**关键差异**：DittoShell 的「写」只有三种：
1. **改分组**（`lParentID`，可逆）
2. **改标签**（sidecar，可逆）
3. **删条目**（`DELETE FROM Main`，有备份但不可逆）

---

### 2.2 权限模式设计（3 档）

| 模式 | 允许的工具 | 危险操作 | 默认 |
|---|---|---|---|
| **只读** 🔒 | `search` `get_detail` `get_context` `get_stats` `list_groups` `list_tags` `find_duplicates` | ❌ 全禁 | |
| **安全** 🛡️ | 只读 + `organize` `add_tag` `export` | 每次弹确认 | ✅ **默认** |
| **完全** ⚡ | 全部（含 `delete` `move_to_group` `clear_group`） | 直接执行 | |

**UI**：状态栏左侧一个下拉

```
┌────────────────────────────────┐
│ 🔒 只读  ▾                     │
└────────────────────────────────┘
   ↓ 点击
┌────────────────────────────────┐
│ ✓ 🛡️ 安全（改数据前确认）      │
│   ⚡ 完全（直接执行）          │
│   🔒 只读（只查不改）          │
└────────────────────────────────┘
```

**实现**：
```csharp
public enum AiPermissionLevel
{
    ReadOnly,      // 只读
    Safe,          // 安全（默认）
    FullAccess     // 完全
}

// AiTools.ExecuteAsync 里
if (IsWriteTool(toolName) && _permission == AiPermissionLevel.ReadOnly)
    return "权限不足：当前是只读模式，无法执行写操作";

if (IsDangerousTool(toolName) && _permission == AiPermissionLevel.Safe)
{
    // 弹确认
    var ok = await _confirm(toolName, args);
    if (!ok) return "用户拒绝了此操作";
}
```

### 2.3 计划模式设计

**触发**：
1. 输入框输入 `/plan <需求>`
2. 或点状态栏的「计划」按钮

**行为**：

```
┌─────────────────────────────────────────────────┐
│ 📋 计划模式已开启                                │
│ 我会先探索，给出方案，你批准后才执行            │
└─────────────────────────────────────────────────┘
```

**AI 收到注入的 prompt 段**：

```
【当前是计划模式】
你只能调用只读工具（search / get_detail / get_context / stats / list_groups 等）。
先充分探索数据，然后把完整方案通过 exit_plan_mode 提交给用户评审。
禁止调用 organize / delete / add_tag 等写工具。
```

**关键**：**计划模式下强制禁用写工具**（比 DSH 更严格，因为剪贴板数据更敏感）。

**`exit_plan_mode` 工具**：

```json
{
  "name": "exit_plan_mode",
  "parameters": {
    "plan": "string — 完整的执行计划（markdown）"
  }
}
```

**UI 呈现**：

```
┌──────────────────────────────────────────────────────┐
│ 📋 执行计划                                          │
├──────────────────────────────────────────────────────┤
│                                                      │
│ 找到 42 条含 "sk-" 开头的 API 密钥，分散在 3 个组：  │
│ · 未归类 28 条                                       │
│ · 项目A 9 条                                         │
│ · 测试 5 条                                          │
│                                                      │
│ 计划：                                               │
│ 1. 新建分组「凭据 > API 密钥」                       │
│ 2. 把这 42 条移入该组                                │
│ 3. 统一打上标签「API密钥」                           │
│                                                      │
│ 预计影响：42 条（不会删除任何内容）                  │
│                                                      │
├──────────────────────────────────────────────────────┤
│ [取消]                    [继续规划]  [批准并执行]   │
└──────────────────────────────────────────────────────┘
```

**点「继续规划」可输入反馈**，AI 重新规划。

### 2.4 目标模式设计

**触发**：
1. 输入框输入 `/goal <长期目标>`
2. 或 AI 自己判断任务复杂，主动 `create_goal`

**示例目标**：

```
/goal 把所有重复的条目清理掉，每组只保留最新的
```

```
/goal 把 2,000 条未归类的条目全部整理到合适的组里
```

**状态机**（同 DSH）：

```
active ──┬── complete ──→ completed
         ├── pause ─────→ paused ──resume──→ active
         └── blocked ───→ blocked（3+ 轮同一阻塞条件）
```

**自动续跑**：

```
第 1 轮：AI 处理一批（比如 60 条）→ 汇报进度
  
  【目标】整理 2,000 条未归类条目
  【进度】已处理 180 / 2,000
  【本轮总结】新建了 4 个分组，移动了 180 条
  
  ↓ 目标未完成 → 自动发起第 2 轮
第 2 轮：…
  ↓
第 N 轮：全部完成 → 标记 completed
```

**UI**：

```
┌────────────────────────────────────────────────────┐
│ 🎯 目标：整理 2,000 条未归类条目                   │
│   第 12 轮 · 已处理 720/2000（36%）                │
│   ▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░                    │
│                                    [暂停] [放弃]  │
└────────────────────────────────────────────────────┘
```

**限制**：
- **每会话一个 goal**（同 DSH）
- 默认最多 **30 轮**（比 DSH 的 256 少，因为剪贴板场景不需要那么多）
- **每轮最多改 200 条**（防止一轮太久）

## 三、三者的关系

```
权限模式 ──── 管「能碰什么」      ← 底层约束
    ↓
计划模式 ──── 管「先想后做」      ← 流程约束
    ↓
目标模式 ──── 管「多轮做完」      ← 时间跨越
```

**组合使用**：

| 组合 | 效果 |
|---|---|
| 完全权限 + 计划模式 | 先规划，批准后直接执行（不逐条确认） |
| 安全权限 + 目标模式 | 多轮执行，但每轮的危险操作都要确认 |
| 只读 + 计划模式 | 只探索出方案，永远不执行 |

**互斥**：
- 计划模式激活时，**权限模式自动降为只读**（AI 不能写）
- 计划批准后，恢复原权限模式

## 六、优先级建议

| # | 功能 | 价值 | 工作量 | 建议顺序 |
|---|---|---|---|---|
| 1 | **权限模式** | 高（安全基础） | 150 行 | **第 1** |
| 2 | **计划模式** | 高（防误操作） | 250 行 | **第 2** |
| 3 | **目标模式** | 中（大任务） | 400 行 | **第 3** |

**理由**：
- 权限是**基础**，没有它，计划和目标都没有安全边界
- 计划模式**依赖**权限（计划模式下强制只读）
- 目标模式**依赖**前两者（每轮执行受权限约束，大任务可能需要先规划）

## 八、还有一个问题

**权限模式要不要跟「AI 整理」共用？**

现在「AI 整理」是独立窗口，有自己的约束系统（6 个硬开关 + 自然语言）。

**如果共用**：
- 整理窗口的开关 → 映射到权限模式
- 对话和整理用同一套权限

**如果分开**：
- 对话：权限模式（三档）
- 整理：约束系统（6 开关）
- **两套系统，用户要学两遍**

**我建议共用**：

```
权限模式（三档）作为「总闸」
  ↓
整理窗口的 6 个开关是「细则」
  ↓
完全权限时 6 个开关都可调
只读时整理窗口整体禁用
```
