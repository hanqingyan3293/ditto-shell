## A. 项目定位

| # | 决策项 | 结论 | 理由 |
|---|---|---|---|
| D01 | 项目性质 | 自用 + 开源（GPL v3），开发期不发布 | 达到"完整可发布"状态后再公开 |
| D02 | 与 Ditto 的关系 | **不改 Ditto 本体**，做独立外壳进程 | MFC 重编译成本与风险过高 |
| D03 | 目标用户 | 已在用 Ditto 的人 | 不内置分发 Ditto，避开 GPL 分发义务 |
| D04 | 明确不做 | 云同步 / 多机 / 手机端 / 密码管理 / 插件机制 | 边界清晰，省掉大量复杂度 |

## B. 技术栈

| # | 决策项 | 结论 | 备选与否决原因 |
|---|---|---|---|
| D05 | 语言/框架 | **WPF + .NET 8** | Tauri 冷启动 600ms+、内存 100MB+；WinUI3 部署重、Win10 受限 |
| D06 | 进程模型 | **单进程 / 双窗口** | 双进程内存翻倍、IPC 复杂 |
| D07 | 分层 | **4 层**：UI → ViewModel → Service → Infrastructure | 3 层会 UI 与业务纠缠；5 层对单人项目过度 |
| D08 | MVVM | CommunityToolkit.Mvvm | 微软官方、源生成器、体积小 |
| D09 | 数据库驱动 | Microsoft.Data.Sqlite + SQLitePCLRaw.bundle_e_sqlite3 | 官方；`e_sqlite3` 自带 FTS5/JSON1 编译 |
| D10 | UI 组件 | 手写样式为主；WPF-UI 仅备选 | 避免依赖第三方主题库的 Win10 兼容风险 |
| D11 | 全局热键 | 自写 P/Invoke `RegisterHotKey` | 二十行代码，不引库 |
| D12 | HTTP | `System.Net.Http` + `System.Text.Json` | 内置 |
| D13 | 图标 | Segoe MDL2 / Segoe Fluent Icons 系统字体 | 零体积 |
| D14 | 分发 | 绿色 zip + 自包含 .NET 运行时 | 用户无需安装 .NET |
| D15 | 最低系统 | Windows 10 1809 (Build 17763) | 用户实测环境 Win10 22H2 / DPI 125% |

## C. 搜索（重要变更）

| # | 决策项 | 结论 | 依据 |
|---|---|---|---|
| D16 | 全文检索方案 | **放弃 FTS5，用 `LIKE '%kw%'` 全表扫描** | 实测 6,179 条耗时 6–11ms；FTS5 trigram 对 2 字中文词 0 召回（详见 04-data-spec） |
| D17 | 索引文件 | **不建** | 省 20–30MB 磁盘 + 砍掉索引同步模块 |
| D18 | 语法 | 前缀式 + `/` 命令面板 | `g:` `tag:` `type:` `app:` `date:` `re:` `secret:` `ai:` |

## D. 数据访问

| # | 决策项 | 结论 | 约束 |
|---|---|---|---|
| D19 | Ditto.db 读 | 只读 `mode=ro` | 绝不 ALTER / 不删行 / 不改 PRAGMA |
| D20 | Ditto.db 写 | 仅 3 字段 + 新建分组 | `lParentID` / `stickyClipOrder` / `stickyGroupOrder` / `lDontAutoDelete` |
| D21 | 写前置条件 | 强制备份 → 单事务 → 完成后 `WM_REFRESH_VIEW` | 失败自动回滚 |
| D22 | 标签/索引 | 独立 `data/sidecar.db` | 不把元数据塞进 Ditto.db |
| D23 | 图片存储 | 沿用 Ditto 的 `CF_DIB` 原始位图，不转码不迁移 | 显示时解码 + 内存 LRU，不落盘 |
| D24 | Ditto 设置 | 读写 `Ditto.Settings`（UTF-16LE INI） | 按行编辑，未知键原样保留 |
