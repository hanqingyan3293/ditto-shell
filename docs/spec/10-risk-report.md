## 4. 应急预案

| 场景 | 立即动作 | 后续 |
|---|---|---|
| `Ditto.db` 疑似损坏 | 停止所有写操作；用 `backup/` 最新备份覆盖；界面只读 | 分析日志找原因 |
| 分组数据错乱 | 从最近备份恢复该库；提示用户核对分组 | 检查写入逻辑 |
| API Key 泄漏 | 设置页「清除 Key」；提示去厂商后台轮换 | 检查日志是否有记录 |
| 误删大量条目 | 无自动恢复（Ditto 的 `MainDeletes` 机制限制）→ 从 `backup/` 恢复 | 增加删除前确认 |
| 外壳崩溃循环 | 启动安全模式（不加载 AI、不做写操作） | 收集日志 |

## 6. 风险接受声明

以下风险**经评估后接受，不做处理**：

| 风险 | 接受理由 |
|---|---|
| `Ditto.db` 明文存储（本机任何程序可读） | Ditto 的设计如此，改加密会破坏兼容性；不属于本项目范围 |
| 用户可能把 Key 填进错误的服务 | 用户自填自担，提供「测试连接」降低误配 |
| 单点故障（外壳崩溃时无法用新界面） | Ditto 原界面兜底 |
| Win10 无 Mica 效果 | 系统限制，已用纯色+自绘阴影替代 |
