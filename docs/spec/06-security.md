# 06 · 安全与隐私

> 核心原则：**剪贴板内容是全网最脏的输入之一，按不可信处理。**

---

## 1. 资产清单

| 资产 | 敏感度 | 现状 |
|---|---|---|
| 剪贴板历史（6,179 条） | 🔴 高 | 含明文 GitHub Token（已实测发现 1 条） |
| `Ditto.db`（830MB） | 🔴 高 | **未加密**，本机任何程序可读 |
| `Ditto.Settings` | 🟡 中 | 含热键、路径、统计 |
| API Key | 🔴 高 | 用户自填 |
| `sidecar.db` | 🟡 中 | 标签、来源应用（能反推用户行为） |
| 日志 | 🟢 低 | 不含正文 |

## 2. 威胁模型

| # | 威胁 | 攻击者 | 攻击面 | 缓解 |
|---|---|---|---|---|
| T1 | 本机其他程序读取剪贴板历史 | 恶意软件 | `Ditto.db` 未加密 | **不在本项目范围**（Ditto 的设计如此）；但外壳不扩大暴露面 |
| T2 | 云端 AI 外泄凭据 | API 提供方 / 中间人 | HTTPS 请求体 | 只发选中项 + 本地脱敏 + 黑名单分组 + HTTPS 强制 |
| T3 | 剪贴板恶意内容注入 | 网页/文档 | 含 HTML/脚本的内容 | **纯文本渲染**，HTML 只做转义预览，不用 WebView |
| T4 | 误提交数据库/密钥到 git | 自己 | 仓库 | `.gitignore` + 发布前体检脚本 |
| T5 | sidecar 损坏 | 断电 | sqlite 文件 | 备份 + 自动重建 |
| T6 | 被篡改的 `Ditto.db` | 第三方 | 文件替换 | 读前校验 `PRAGMA integrity_check`（抽样）；异常则只读降级 |
| T7 | 权限提升 | — | 管理员窗口粘贴 | 不请求管理员权限；粘贴到管理员窗口由 Ditto 的 `/uacpaste` 机制处理 |

## 3. 信任边界

```
┌──────────────────────────────────────────────┐
│ 完全信任：外壳进程自身                        │
├──────────────────────────────────────────────┤
│ 半信任：Ditto.db / Ditto.Settings             │
│   → 只读为主；写入仅限白名单字段；读后校验      │
├──────────────────────────────────────────────┤
│ 不可信：剪贴板内容                            │
│   → 纯文本渲染；不执行；不自动打开链接          │
├──────────────────────────────────────────────┤
│ 外部：DeepSeek API                            │
│   → 只发选中项；响应当数据看，不当指令执行      │
└──────────────────────────────────────────────┘
```

### 3.1 剪贴板不可信的具体规则

| 内容类型 | 处理 |
|---|---|
| 纯文本 | 直接显示 |
| HTML Format | 只提取纯文本显示；原始 HTML 不渲染、不注入 WebView |
| RTF | 同上，只取纯文本 |
| 图片（CF_DIB） | 解码后显示；解码失败显示占位图 |
| 文件路径（CF_HDROP） | 只显示路径字符串，**不自动打开** |
| URL | 显示为文本；点击时**二次确认**是否用浏览器打开 |
| 含控制字符 | 过滤/替换为可见符号 |

## 4. 敏感信息识别（本地，不联网）

### 4.1 正则规则集

| 类型 | 正则 |
|---|---|
| GitHub Token (classic) | `gh[pousr]_[A-Za-z0-9]{36,255}` |
| GitHub Token (fine-grained) | `github_pat_[A-Za-z0-9_]{82}` |
| AWS Access Key | `AKIA[0-9A-Z]{16}` |
| 私钥 | `-----BEGIN [A-Z ]*PRIVATE KEY-----` |
| 中国身份证 | `[1-9]\d{5}(18\|19\|20)\d{2}(0[1-9]\|1[0-2])(0[1-9]\|[12]\d\|3[01])\d{3}[\dXx]` |
| 银行卡 | `\b\d{16,19}\b` + Luhn 校验 |
| 密码赋值 | `(?i)(password\|passwd\|pwd\|密码)\s*[:=]\s*\S{4,}` |
| 连接串 | `(?i)(mongodb\|mysql\|postgres\|redis\|amqp)://[^\s"']+` |
| JWT | `eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}` |

### 4.2 命中后行为

| 场景 | 行为 |
|---|---|
| 列表显示 | 类型标红 + 「敏感」标签；正文**打码**（保留前 6 后 4 字符） |
| 粘贴 | 正常粘贴原内容（用户明确要求，不阻断） |
| 发往 AI | **拒绝并提示**「这条含疑似凭据，已阻止发送」+ 「仍要发送」二次确认 |
| 导出 | 提示「包含 N 条敏感内容」 |

### 4.3 性能

6179 条 × 9 条正则 ≈ 每条约 5–15 µs → 全量扫描约 50–90ms（后台跑，不阻塞 UI）。

## 5. AI 数据边界

```
发送前检查链：
1. 是否用户主动选中？          否 → 不发送
2. 是否在黑名单分组？          是 → 拒绝
3. 敏感检测是否命中？          是 → 打码或阻止
4. 内容长度 > 8000 字？        是 → 截断 + 提示
5. 发送（HTTPS，只带必要字段）
```

| 项 | 规则 |
|---|---|
| 发送内容 | 仅：选中的文本片段 + 系统提示词 |
| 绝不发送 | 全量历史、文件路径、来源应用名、标签、设置 |
| 请求日志 | 只记「发送了 N 字符」，**不记正文** |
| 响应缓存 | 仅缓存摘要文本，存 `sidecar.ai_cache`，可在设置里一键清空 |
| 超时 | 30s |
| 失败 | 不重试超过 1 次，提示用户 |

## 6. API Key 管理

| 项 | 做法 |
|---|---|
| 存储 | Windows 凭据管理器（`Credential Manager`，target = `DittoShell/DeepSeek`） |
| 配置文件 | 只存 `"aiKeyRef": "DittoShell/DeepSeek"`，不存明文 |
| 内存 | 用完即清（`SecureString` 或尽快置空 char[]） |
| 日志 | **永不记录** |
| 界面 | 输入框掩码显示，只可整体替换，不可查看 |
| 导出设置 | 默认**不含** Key |

## 7. 备份策略

| 触发 | 备份对象 | 目标 | 保留 |
|---|---|---|---|
| 首次写 `Ditto.db` 前（5 分钟内只备一次） | `Ditto.db` | `backup/Ditto_*.db` | 最近 10 份 |
| 首次写 `Ditto.Settings` 前 | `Ditto.Settings` | `backup/Ditto.Settings_*.ini` | 最近 10 份 |
| sidecar 迁移前 | `sidecar.db` | `backup/sidecar_*.db` | 最近 5 份 |
| 手动「一键备份」 | 全部 | `backup/` | 不自动删 |

清理：只自动清理**自动生成的**备份，手动备份永不自动删。

## 8. 许可证与分发

| 项 | 结论 |
|---|---|
| 本项目许可证 | **GPL v3** |
| 发布包 | 必须附源码（或指向公开仓库的明确链接） |
| 分发 Ditto | **不做**（不内置），避免承担 Ditto 的分发义务 |
| 第三方依赖 | 全部为 MIT / Apache-2.0 / MS-PL，无冲突 |
| 发布前检查 | 仓库中不得含 `Ditto.db` / `*.zdb` / Key / 个人路径 |

---

## 9. 日志规范

| 记 | 不记 |
|---|---|
| 时间、模块、级别 | **剪贴板正文** |
| 操作类型（打开/搜索/粘贴/写库） | 文件完整路径（只记文件名） |
| 耗时、条数 | API Key、Token |
| 异常堆栈 | 用户输入的原内容 |

日志级别：`INFO` 默认，`DEBUG` 仅开发版，`ERROR` 永远记录。
