## 我们项目里的词

| 词 | 什么意思 |
|---|---|
| **引擎** | Ditto.exe 本体，我们不改它 |
| **外壳 / 前端** | 我们自己做的界面程序（DittoShell） |
| **旁路库 / sidecar** | 我们自己建的数据库文件，存标签和索引，坏了删掉重建 |
| **标签 / tag** | 我们加的标记，一个条目可以贴多个（和 Ditto 的"组"不同） |
| **虚拟分组** | 不实际存储、靠条件算出来的分组，比如「今天」「图片」 |
| **只读 / read-only** | 只能看，不能改。一期全程只读 |
| **备份 / backup** | 改动前先复制一份，出事能还原 |
| **回滚 / rollback** | 撤销这次改动，回到之前的状态 |
| **迁移 / migration** | 数据库结构升级的步骤 |

## 容易混淆的三组概念

**1. 「组」 vs 「标签」**
- Ditto 的**组**：像文件夹，一条内容只能放进一个文件夹
- 我们的**标签**：像便利贴，一条内容可以贴很多张

**2. 「预览文本」 vs 「全文」**
- 预览文本（`mText`）：只有前 900 字，Ditto 列表里显示的就是它
- 全文：存在 `Data` 表里的完整内容 —— **搜索要用全文，不然长文本搜不全**

**3. 「Ditto 的界面」 vs 「我们的外壳」**
- 两个都能用，看同一个数据库
- 我们的外壳挂了，Ditto 照常工作
